2. ОБЩАЯ ЦЕЛЬ СИСТЕМЫ (сквозной сценарий)
--------------------------------------------------------------------------------
ЛР1  Генератор шаблона: A4-бланк с 4 ArUco-маркерами + поля ответов.
      ГОТОВО. Не трогать.
ЛР2  Нормализатор: фото -> aligned_blank.png (2100x2970) + edges.png.
ЛР3  ROI-спецификация + нарезка + манифест датасета (crops, labels.csv,
      dataset_manifest.json, сплиты по photo_id).
ЛР4  CNN-классификатор + custom training loop (без model.fit),
      Macro-F1, чекпоинты, confusion matrix.
ЛР5  Экспорт в TFLite (динамическое квантование), DAG-оркестратор,
      детерминированный Checker (CORRECT/INCORRECT/NEEDS_REVIEW),
      интерфейс (Web + CLI), Settings из GUI/CLI.

Сквозной поток:
  шаблон -> печать -> заполнение -> фото/скан ->
  нормализация -> нарезка ROI -> (обучение CNN) -> TFLite ->
  DAG: CV -> Extraction -> ML -> Checker -> GradeResult.

--------------------------------------------------------------------------------
3. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ (НЕ МЕНЯТЬ)
--------------------------------------------------------------------------------
Интерфейс: Web (FastAPI + Jinja2 + vanilla JS) как основной; CLI как второй
адаптер; Desktop — опционально. Домены про HTTP/UI не знают.

Единственный DAG-оркестратор: serving/pipeline.py.
normalizer/aligner.py — это не «pipeline», а CV-узел. Избегаем коллизии имён.

TemplateSpec — единственный источник истины о «правильном листе»:
template_version, canvas_size, roi_fields (id, type, coords), + расширения
(dictionary_id, expected_marker_ids, corner_by_id, marker_layout,
marker_size_px, padding_px, per-field confidence_threshold).
Формат строго совместим с ТЗ ЛР3; расширения аддитивны.
Генератор (ЛР1) заполняет roi_fields автоматически из
template_layout.json; пустой roi_fields у нового шаблона — ошибка
конфигурации, а не норма.

AnswerKey — отдельный файл: template_version, answers: dict[field_id -> str].
field_id совпадают с roi_fields[].id. При несовпадении — AnswerKeyMismatchError.

Привязка маркеров к углам (corner_by_id), каноническая раскладка:
  ID 0 -> TL, ID 1 -> TR, ID 2 -> BR, version_marker_id -> BL.
  Физические ID задаются в template_layout.json:
    markers.ids.TL = 0, markers.ids.TR = 1, markers.ids.BR = 2,
    markers.ids.BL отсутствует — BL всегда version_marker_id (3..49).
  Единственная точка истины в коде — resolve_marker_ids() в
  template/generator.py; её обязаны использовать и генератор спеки,
  и рендерер DOCX. Дублировать раскладку в рендерере запрещено.
Режимы углов (corner_mode), дефолт для сдачи — "centers" (буква ТЗ ЛР2):
  centers             — центры маркеров -> углы прямоугольника;
  centers_to_layout   — центры маркеров -> marker_layout (сохраняет поля);
  outer_corners       — внешние углы маркеров -> углы прямоугольника.
Trade-off центров оговорить в отчёте.

Источник истины по ID: TemplateSpec авторитетен; AlignConfig.expected_ids —
фолбэк CLI/отладки без спеки.

Ошибки типизированы. Домены кидают кастомные исключения; DAG Fail-Fast:
любое исключение узла прерывает конвейер. HTTP-маппинг — единый handler.

Инференс в api — только через tflite.Interpreter (tflite-runtime или
ai-edge-litert). Импорт tensorflow/tensorflow.keras в api и serving ЗАПРЕЩЁН.
TensorFlow живёт только в trainer (offline).

TfliteRunner — пул интерпретаторов (InterpreterPool, pool_size из Settings,
дефолт 4). API — синхронные def (FastAPI уводит в threadpool).

Checker — детерминированный. Порог θ из Settings (дефолт 0.80), per-field
override в TemplateSpec. Статусы: CORRECT / INCORRECT / NEEDS_REVIEW.
Итоговый балл считается БЕЗ NEEDS_REVIEW (они уходят на ручную проверку).

Settings — единый источник runtime-настроек (Pydantic). Меняется через
Web-вкладку «Настройки» и CLI `settings`; пробрасывается в CLI-флаги и API.

Jobs — для batch и тяжёлых прогонов. POST /api/grade — синхронный для
одного фото; POST /api/grade/batch -> job_id; GET /api/jobs/{id} -> статус.

MVP: один лист в кадре. >4 маркеров -> UnexpectedMarkerCountError.

6. КОНТРАКТЫ ДАННЫХ (Pydantic v2)
--------------------------------------------------------------------------------
class RoiField(BaseModel):
    id: str
    type: Literal["digit", "text", "checkbox", "handwriting"]
    coords: tuple[int, int, int, int]           # x, y, w, h в 2100x2970
    confidence_threshold: float | None = None   # per-field override

class TemplateSpec(BaseModel):
    template_version: str
    canvas_size: tuple[int, int] = (2100, 2970)
    roi_fields: list[RoiField]           # заполняется генератором; не пустой
    # расширения (аддитивны к формату ТЗ ЛР3):
    dictionary_id: int = cv2.aruco.DICT_4X4_50
    expected_marker_ids: list[int] = [0, 1, 2, 3]
    corner_by_id: dict[int, Literal["TL","TR","BR","BL"]] = {0:"TL",1:"TR",2:"BR",3:"BL"}
    marker_layout: dict[int, tuple[int, int]] | None = None
    marker_size_px: int | None = None
    padding_px: int = 5

class AlignConfig(BaseModel):
    dictionary_id: int = cv2.aruco.DICT_4X4_50
    expected_ids: tuple[int, ...] = (0, 1, 2, 3)   # фолбэк CLI без TemplateSpec
    output_size: tuple[int, int] = (2100, 2970)
    border_value: tuple[int, int, int] = (255, 255, 255)
    canny_thresholds: tuple[int, int] = (50, 150)
    strict_marker_count: bool = True
    corner_mode: Literal["centers","centers_to_layout","outer_corners"] = "centers"
    min_quad_area_px: int = 100_000

class AlignResult(BaseModel):
    marker_ids: list[int]
    source_points: list[tuple[float, float]]       # TL,TR,BR,BL
    dst_points: list[tuple[float, float]]
    homography: list[list[float]]
    output_size: tuple[int, int]
    corner_mode: str
    warnings: list[str]
    # output_image/edges_image — numpy, передаются отдельно, не в Pydantic

class CropBatch(BaseModel):
    template_version: str
    crops: list[dict]                             # {field_id, coords, path|bytes}
    normalized_size: tuple[int, int] | None       # если normalize=True

class AnswerKey(BaseModel):
    template_version: str
    answers: dict[str, str]                       # field_id -> expected_label

class FieldGrade(BaseModel):
    field_id: str
    predicted: str | None
    confidence: float | None
    status: Literal["CORRECT","INCORRECT","NEEDS_REVIEW"]

class GradeResult(BaseModel):
    template_version: str
    photo_id: str
    fields: list[FieldGrade]
    score: float
    max_score: float
    needs_review: list[str]
    warnings: list[str] = []

class JobStatus(BaseModel):
    job_id: str
    state: Literal["queued","running","done","error"]
    progress: float                               # 0..1
    result: GradeResult | None = None
    error: dict | None = None

class Settings(BaseModel):
    confidence_threshold: float = 0.80
    canny_thresholds: tuple[int, int] = (50, 150)
    corner_mode: Literal["centers","centers_to_layout","outer_corners"] = "centers"
    padding_px: int = 5
    output_size: tuple[int, int] = (2100, 2970)
    tflite_pool_size: int = 4
    batch_size: int = 1                           # для grade/batch
    split_ratios: tuple[float, float, float] = (0.70, 0.15, 0.15)
    learning_rate: float = 0.001
    epochs: int = 30
    train_batch_size: int = 32

class TrainingConfig(BaseModel):
    learning_rate: float = 0.001
    epochs: int = 30
    batch_size: int = 32
    split_ratios: tuple[float, float, float] = (0.70, 0.15, 0.15)
    label_encoding: Literal["one_hot","integer"] = "integer"
    input_shape: tuple[int, int, int] = (64, 128, 1)
    num_classes: int

class FieldRecognizer(Protocol):
    def predict(self, crops: list) -> list[tuple[str, float]]: ...
    # возвращает [(predicted_label, confidence), ...]

Контракт template_layout.json (расширение, не ломает ТЗ ЛР1):
  markers.ids: {TL: 0, TR: 1, BR: 2}
  markers.positions: {TL, TR, BR, BL} в мм
  question_columns_mm: [num_w, question_w, answer_w]
  roi.table_top_mm:   абсолютная Y-позиция таблицы на странице, мм
  roi.row_height_mm:  фиксированная высота строки вопроса, мм
  roi.padding_px:     padding для roi_fields
Генератор и рендерер читают одни и те же поля. Изменение
roi.table_top_mm / roi.row_height_mm / question_columns_mm меняет
и DOCX, и координаты roi_fields — это требование ЛР3, а не баг.
Версия маркера: BL = content.version_marker_id (3..49); TL/TR/BR
берутся из markers.ids. Старый формат спеки (template_id, version,
rois, created_at) несовместим: такие файлы нужно перегенерировать.

7. ДОМЕННЫЕ ОШИБКИ И HTTP-КОДЫ
--------------------------------------------------------------------------------
Единый handler в FastAPI и CLI. Тело ошибки:
  {"code": "...", "message": "...", "details": {...}}
UI — человекочитаемое сообщение, не traceback.

  ImageReadError                 -> 400
  InvalidImageError              -> 400
  CropOutOfBoundsError           -> 400
  JobNotFoundError               -> 404
  UploadTooLargeError            -> 413
  DocumentAlignmentError (базовая)-> 422 (или 500, если не частный случай)
  MarkersNotFoundError           -> 422
  MarkersIncompleteError         -> 422
  UnexpectedMarkerCountError     -> 422
  DuplicateMarkerIdsError        -> 422
  MarkerIdsMismatchError         -> 422
  TemplateSpecMismatchError      -> 422
  AnswerKeyMismatchError         -> 422
  ConfigError                    -> 422
  RoiExtractionError             -> 422
  HomographyError                -> 500
  WarpError                      -> 500
  TfliteLoadError                -> 500
  TfliteInferenceError           -> 500
  CheckerError                   -> 500
  неизвестное                    -> 500

Вырожденность гомографии (HomographyError):
  площадь < AlignConfig.min_quad_area_px; коллинеарные точки;
  np.linalg.matrix_rank(H) < 3; координаты NaN/Inf.

Fail-Fast в DAG: любое из перечисленных исключений прерывает pipeline.py.

Технические требования:
  - /api/align, /api/extract, /api/grade — синхронные def (threadpool).
  - /api/grade/batch — создаёт job, возвращает сразу; обработка в
    ThreadPoolExecutor или фоновом воркере.
  - Проверка max_upload_mb до чтения в память.
  - Форматы: JPEG, PNG; валидация MIME + imdecode.
  - I/O Efficiency: не писать upload на диск; cv2.imdecode(np.frombuffer(...)).
  - NormalizerService.align принимает путь / bytes / np.ndarray и сам
    вызывает read_image. API передаёт сырые bytes; передавать bytes
    напрямую в aligner.align() запрещено (там ожидается np.ndarray).
  - /api/align всегда возвращает aligned_image и edges_image (data URL),
    независимо от save_aligned/save_edges. Запись artifacts на диск —
    опциональна; Web UI не должен делать второй запрос за картинками.
  - InterpreterPool: pool_size из Settings; TFLite invoke под захватом
    интерпретатора из пула.
  - Graceful Degradation: кастомные исключения -> HTTP-код + JSON.

  Генерация шаблона (ЛР1):
  python generate_blank.py --layout template_layout.json \
      --content content_vN.json --output output\blank_vN.docx \
      [--template-id <id>]
  Спека пишется рядом: output\blank_vN.spec.json.
  --template-id нужен для воспроизводимости (иначе генерируется
  случайный template_version).

Exit codes:
  0 — успех
  2 — доменная ошибка (маркеры, ID, гомография, спека, ключ, конфиг)
  3 — I/O (не прочитан вход, не записан выход)
  4 — ошибка обучения/экспорта (train, export-tflite)
Никаких traceback в stdout; полный traceback — в лог.

settings CLI и Web-вкладка «Настройки» пишут в один и тот же Settings
(runtime-конфиг). Приоритет: CLI-флаг > Settings > дефолт.

12. ПРИНЦИПЫ КОДА
--------------------------------------------------------------------------------
Домены не знают про HTTP/UI. Сервисы принимают numpy/модели, возвращают модели.
DAG (serving/pipeline.py) — единственная точка оркестрации.
Нормализатор/roi/training/serving не импортируют FastAPI.
Импорт tensorflow/tensorflow.keras в api и serving запрещён (проверяется тестом).
Ошибки типизированы, единый handler в FastAPI и CLI.
Pydantic-схемы в core/schemas.py, общие для API, CLI и доменов.

I/O Efficiency: upload не пишется на диск, декодируется в память.
Thread/Async isolation: CPU-bound вынесен из event loop (def-эндпоинты,
ThreadPoolExecutor, InterpreterPool).
Graceful Degradation: любое исключение домена -> понятное сообщение,
сервис не падает.
TemplateSpec.template_version — при несовместимых изменениях старые шаблоны
конвертируются или отклоняются (TemplateSpecMismatchError), не «тихо ломаются».

16. ВНЕШНИЕ КОНТРАКТЫ И СОВМЕСТИМОСТЬ С ЧУЖИМ ТЗ/SKILL
--------------------------------------------------------------------------------
Пользователь может передавать этот SKILL вместе с ТЗ и SKILL другой
нейросети. Правила совместимости:

TemplateSpec: формат ЛР3 (template_version, canvas_size, roi_fields
[id, type, coords]) — обязательный минимум. Расширения (dictionary_id,
expected_marker_ids, corner_by_id, marker_layout, marker_size_px,
padding_px, confidence_threshold) аддитивны; отсутствие расширений —
дефолты из раздела 6.
roi_fields обязателен и непуст: если у чужой спеки roi_fields пуст,
нарезка невозможна — это ошибка конфигурации.

Устаревший формат спеки (template_id, version, rois, created_at) не
поддерживается: такие файлы нужно перегенерировать текущим генератором
(DOCX + TemplateSpec). Автоматическая миграция не выполняется, чтобы не
угадывать геометрию; при загрузке старой спеки — понятная ошибка.

AnswerKey: отдельный файл; field_id == roi_fields[].id. Если чужой ТЗ
использует другую структуру — адаптер в serving/answer_key.py;
при несовпадении — AnswerKeyMismatchError с понятным сообщением и
списком отсутствующих/лишних id.

Settings: единый источник для Web/CLI/API. Чужие CLI-флаги маппятся
на поля Settings в cli.py; приоритет: CLI-флаг > Settings > дефолт.

Имена артефактов: aligned_blank.png, edges.png — из ТЗ ЛР2, не менять.
Остальные имена — из раздела 14; при интеграции с чужим ТЗ, где имена
другие, — маппинг в serving, имена на диске не переименовывать без
согласования.

Алфавит классов (alphabet.json): N классов, порядок фиксирован;
index -> label однозначно. Чужой ТЗ, где порядок другой, — пересобрать
alphabet.json и переобучить/переэкспортировать модель; иначе
предсказания будут неверны.

Если чужой SKILL/ТЗ противоречит разделам 3, 4, 12 (инварианты: нет
tensorflow в api/serving, нет model.fit, DAG-оркестратор, типизированные
ошибки) — приоритет у этого SKILL, расхождение — в отчёт.
